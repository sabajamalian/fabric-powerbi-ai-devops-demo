## Why this matters

Instructions tell Copilot what good work looks like. MCP gives it tools. The Power BI Modeling MCP server lets a chat agent inspect the semantic model that is open in Power BI Desktop, run DAX, and make model changes with your approval. In this lab you connect it in read-first mode, so later agents can test their answers against the live model instead of guessing from files.

## Concepts

- **Model Context Protocol (MCP):** an open protocol that lets VS Code expose external tools to Copilot Chat. See [MCP](/reference/mcp/).
- **Power BI Modeling MCP:** Microsoft's local MCP server for Power BI semantic models. It can connect to Power BI Desktop, Fabric semantic models, or PBIP project files, and it exposes tools for model metadata, DAX queries, relationships, measures, and other modeling operations.
- **Workspace MCP config:** `.vscode/mcp.json` is committed so every learner sees the same server names and pinned package versions. Secrets stay out of this file.
- **Tool approval:** VS Code asks before an MCP server starts and before tools run. The Power BI MCP server also asks before the first query or model edit.
- **File mode:** macOS learners cannot run Power BI Desktop, but they can still read and edit PBIP files. Some Power BI Modeling MCP PBIP operations are documented, but this lab only verifies the live Desktop path on Windows.

### Step 4. Start the MCP server from VS Code

1. Open the Command Palette: **Ctrl+Shift+P** (macOS: **Cmd+Shift+P**), or **View > Command Palette**.
2. Run **MCP: List Servers**.
3. Select **powerbi-modeling-mcp**.
4. Choose **Start Server**. If VS Code says the server is disabled, choose **Enable** first.
5. When the trust dialog appears, select the server configuration link, confirm it points to this workspace's `.vscode/mcp.json`, then select **Trust**.

VS Code's current MCP docs say you can also find installed MCP servers in the Extensions view by searching `@mcp`, and that first start shows a trust prompt for workspace servers.

**You should see:** `powerbi-modeling-mcp` moves to a running state. If this is the first run, `npx` may download the pinned package before the server is ready.

<Checkpoint lab="04" step="4" />

### Step 5. Enable the Power BI tools in agent mode

1. Open Copilot Chat: **Ctrl+Alt+I** (macOS: **Ctrl+Cmd+I**), or **View > Chat**.
2. Switch the chat mode to **Agent** from the mode picker in the chat input.
3. Select **Configure Tools** in the chat input.
4. Expand **powerbi-modeling-mcp**.
5. Leave read tools and DAX query tools selected. Keep write tools selected only if you are ready to approve model edits later.

The Power BI Modeling MCP repo documents tool groups such as `connection_operations`, `model_operations`, `table_operations`, `relationship_operations`, `measure_operations`, and `dax_query_operations`. The exact display names can change while the server is in preview.

**You should see:** Power BI Modeling MCP tools in the tool picker. At minimum, you should see connection and DAX query capabilities. If Fabric MCP tools appear too, you can leave them off for now.

<Checkpoint lab="04" step="5" />

### Step 6. Connect to Desktop and run a safe read

In Agent mode, send this prompt:

```text
Connect to the Power BI Desktop instance that has ContosoPharmacy open. List the tables and row counts, then run a DAX query that returns prescription fill counts by region for 2025-12. Do not change the model.
```

Approve each tool call after you read it. For the Power BI MCP server, expect an approval before the first query. Do not approve any edit or write operation in this lab.

**You should see:** a connection to the open Desktop model, a list of the baseline tables, and DAX results grouped by region. The table names still use the baseline source names, because [Lab 07](/labs/07-handoffs-names-descriptions/) has not renamed them yet.

<WhatVaries mustMatch={['The agent connects to the ContosoPharmacy model open in Desktop', 'No model edits are requested or approved', 'The answer uses Power BI Modeling MCP tools, not invented rows']}>
The exact DAX and row-count wording may vary. Some versions show tool names, and some show only an approval card.
</WhatVaries>

<Checkpoint lab="04" step="6" />

### Step 7. Try the PBIP file-mode path, then stop the server

The Power BI Modeling MCP docs say the server can open a semantic model from a PBIP folder with a prompt like this:

```text
Open semantic model from PBIP folder 'fabric/ContosoPharmacy.SemanticModel/definition' in read-only mode and list the tables.
```

Use this as an exploration path only. I verified the repo configuration and the public documentation that describe PBIP support. I could not verify that offline PBIP mode returns data rows on macOS, and it should not replace the Desktop path for Labs 05, 08, or 10.

To stop the server:

1. Open **MCP: List Servers** from **View > Command Palette**.
2. Select **powerbi-modeling-mcp**.
3. Choose **Stop Server**.

**You should see:** file-mode metadata if your server version supports it, or a clear error that the operation needs a different path or Desktop connection. After stopping, the server shows as stopped in **MCP: List Servers**.

## Troubleshooting

<details>
<summary>MCP: List Servers does not show powerbi-modeling-mcp</summary>

Open `.vscode/mcp.json` and confirm it still has the `powerbi-modeling-mcp` server. Then run **Developer: Reload Window** from **View > Command Palette**. If your organization disables MCP servers in Copilot, VS Code can read the file but not expose the tools.

</details>

<details>
<summary>The server starts, then fails with an npx or Node error</summary>

Run `node --version` in the VS Code terminal. The lab expects Node.js 20 or later. If Node works, open **MCP: List Servers > powerbi-modeling-mcp > Show Output** and read the first error. Corporate proxies often block the first `npx` package download.

</details>

<details>
<summary>The agent cannot find Power BI Desktop</summary>

Make sure Desktop is open with `fabric\ContosoPharmacy.pbip`, not just the welcome screen. Select **Home > Refresh** once and wait for the spinner to finish. The local Analysis Services port file appears only after the model is loaded.

</details>

<details>
<summary>The tools are available but Copilot never calls them</summary>

Open Copilot Chat, switch to **Agent** mode, select **Configure Tools**, and make sure the Power BI tools are checked. Ask for a specific tool-backed action, for example "connect to the Desktop model and list tables".

</details>

<details>
<summary>I see two Power BI Modeling MCP servers</summary>

You likely have both the VS Code extension and the workspace `npx` server active. Disable one from **MCP: List Servers**. For this lab, keep the workspace server if you want to match the pinned version in `.vscode/mcp.json`.

</details>
