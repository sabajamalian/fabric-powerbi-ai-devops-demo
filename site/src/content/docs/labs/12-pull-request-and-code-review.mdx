## Why this matters

Model-as-code work should end in a pull request, not in a local folder. CI proves the model parses, report bindings resolve, scripts pass, and the lab site still builds. Copilot code review adds another reviewer that reads the diff and the repo instructions. You also compare it with the local `/review-model-pr` prompt so you can see what each surface catches.

## Concepts

- **Pull request:** the review boundary for semantic model, report, and AI metadata changes. See [Branching and pull requests](/reference/branching-and-pull-requests/).
- **CI:** this repo's tenant-free GitHub Actions workflow. It runs on pull requests without Fabric, Power BI, or secrets. See [CI workflows](/reference/ci-workflows/).
- **Copilot code review:** a paid GitHub Copilot feature that you request from the PR sidebar. It leaves comments like a reviewer, usually as a comment review.
- **Local model review:** the `/review-model-pr` prompt with the model-reviewer agent. It can run local validation and focus on Power BI model conventions.
- **Ruleset review:** optional repository settings can request Copilot review automatically on pull requests.

### Step 6. Request Copilot code review

<PlatformBadge kind="paid-plan" />

GitHub Docs say Copilot code review is requested from the PR sidebar.

1. Open the pull request on GitHub.com.
2. In the right sidebar, find **Reviewers**.
3. Next to **Copilot**, select **Request**.
4. Wait for the review to finish. GitHub Docs say it usually takes less than 30 seconds, but busy PRs can take longer.
5. Read each comment. Look for severity labels such as **High**, **Medium**, or **Low**.
6. If you push more commits later, use the re-request button next to Copilot in **Reviewers**.

**You should see:** a Copilot review on the PR and passing checks from step 5. This satisfies the Lab 12 check when the PR comes from a feature branch, not `main` or `master`.

<WhatVaries mustMatch={['The PR head branch is not main or master', 'The status checks are green', 'At least one PR review is authored by Copilot']}>
Copilot may leave no inline comments if it doesn't find issues. The review record still counts.
</WhatVaries>

4. Approve the validation commands after reading them.

### Step 10. Optional: enable automatic Copilot review

<PlatformBadge kind="paid-plan" /> <PlatformBadge kind="optional" />

If this is your own repo and your plan allows it, configure automatic reviews so future PRs don't need a manual request.

1. On GitHub.com, open your repo.
2. Select **Settings > Rules > Rulesets**.
3. Create or edit a ruleset for pull requests into `main`.
4. Add Copilot code review as an automatic review requirement if your UI exposes it.
5. If the UI offers **Review new pushes**, enable it only if you want Copilot to re-review after each push.

**You should see:** future pull requests to `main` request Copilot review automatically. If you don't see the option, your plan or organization policy may not allow it.

## Troubleshooting

<details>
<summary>gh pr create opens against the upstream repo</summary>

Check `git remote -v`. `origin` should be your copy. If `origin` points at `sabajamalian/fabric-powerbi-ai-devops-demo`, rename it to `upstream`, add your copy as `origin`, and push again. Lab 01 step 3 shows the intended remote setup.

</details>

<details>
<summary>Dependency review is skipped or missing</summary>

The `dependency-review` job runs only on pull requests. If you are looking at a push to `main` or a local workflow run, it won't run. The Lab 12 check only needs a PR with green checks and a Copilot review.

</details>

<details>
<summary>Copilot is not shown under Reviewers</summary>

Copilot code review needs a paid plan or organization access, and admins can disable it. Check your GitHub Copilot settings and repository policies. If you're in an organization, ask an owner whether Copilot code review is enabled.

</details>

<details>
<summary>The deliberate break fails a different validation first</summary>

If TMDL lint fails before report bindings, restore the file and make a smaller rename: only change the column object name from `Region` to `Sales Region`. Don't change `sourceColumn`, `lineageTag`, indentation, or DAX. Then push again.

</details>

<details>
<summary>Copilot review comments look generic</summary>

Check that the PR includes the instruction and skill files on the head branch. GitHub Docs say Copilot code review reads custom instructions, agent instructions, and skills from the PR head branch. Also make sure the PR description explains the model changes and includes the question comparison.

</details>
