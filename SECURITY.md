# Security policy

## This repository holds synthetic data only

Everything in this repository is synthetic. The "Contoso Pharmacy" stores, medications, and prescription fills are generated by `tools/python/pharmacy_demo/datagen.py` from a fixed seed. There are no patients, prescribers, people, or health records of any kind.

**Do not use this repository, its scripts, or its workflows to store or process protected health information (PHI), personal data, or customer data.** It isn't designed, reviewed, or configured for that.

## What must never be committed

- Credentials, tokens, client secrets, certificates, or connection strings.
- Tenant IDs, workspace IDs, capacity IDs, subscription IDs, or object IDs.
- Real customer names, internal URLs, or screenshots from a real tenant.
- Power BI Desktop local files: `.pbi/localSettings.json`, `.pbi/cache.abf`, `*.pbix`.

`scripts/Invoke-Validation.ps1` runs an identifier guard that fails on GUIDs, email addresses, and secret-like strings outside an allowlist (`rules/identifier-allowlist.yaml`). CI runs the same guard plus gitleaks. GitHub secret scanning and push protection are enabled on the upstream repository.

## Configuration

Every configuration file in the repo uses placeholders such as `<your-workspace-name>`. The demo needs no Fabric tenant, capacity, workspace, or service principal. If you extend it to deploy to Fabric, use workload identity federation (OIDC) from GitHub Actions and GitHub environments with required reviewers, and keep all identifiers in environment variables or secrets.

## Reporting a vulnerability

Please report security issues privately through GitHub's "Report a vulnerability" button on the Security tab of this repository. Don't open a public issue. You'll get an acknowledgement within five business days.
