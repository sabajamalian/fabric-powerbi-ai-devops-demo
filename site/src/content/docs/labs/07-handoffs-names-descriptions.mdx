## Why this matters

A person reading `fact_rx_fill[proc_mins]` can guess what it means. An AI tool can't, and neither can a new analyst. Business names and one-line descriptions are the cheapest improvement you can make to a semantic model, and they're what Copilot, Q&A, and data agents read first. In this lab you let an agent do the tedious part, and you learn why renames in a model-as-code repo always need a second step: fixing the report that refers to the old names.

## Concepts

- **Handoff:** a button a custom agent shows after it answers. It switches the chat to another agent and pre-fills a prompt, so work moves along a chain (assess, improve, test, review) with context carried over. See [Copilot customization](/reference/copilot-customization/).
- **Prompt file:** a reusable task you run with `/name` in chat. `/improve-names-and-descriptions` scopes this lab's work so the agent doesn't also add measures or change relationships. See [Prompts](/reference/prompts/).
- **Skill loading:** the improver loads `pharmacy-model-conventions` (for the rename map), `tmdl-authoring` (for syntax), and `pbir-rebinding` (for the report). See [Skills](/reference/skills/).
- **Lineage tag:** the stable ID Power BI uses to track an object across renames. It must not change when the name does.

### Step 4. Review descriptions, hidden keys, and summarization

The same prompt continues with descriptions and column properties. When it finishes, review the diff before you accept it.

1. Open **Source Control**: **Ctrl+Shift+G**, or **View > Source Control**.
2. Click `Store.tmdl` to open the diff.
3. Check these on at least one table:
   - Every table and visible column has a `///` description line right above it, under 200 characters.
   - `Store Key` has `isHidden` and `summarizeBy: none`.
   - Numbers that aren't additive, such as `Year`, have `summarizeBy: none`.
   - The `lineageTag:` line of each column is unchanged. The diff shows only the name line and new lines around it.
4. Ask the agent about anything that looks wrong, for example "Why is Open Date not hidden?". It should point to the conventions skill.

Then confirm with the convention check:

```powershell
pwsh ./scripts/Test-ModelConventions.ps1 -Rule C01,C02,C03,C04,C05
```

**You should see:** `0 finding(s)`.

<Aside type="caution" title="If lineageTag changed">
A changed `lineageTag` makes Power BI treat the column as new, which breaks anything built on the old one in the service. Ask the agent to restore the original tags from `git diff`, or discard that file's changes and run the prompt again.
</Aside>

<Checkpoint lab="07" step="4" />

### Step 5. Run the TMDL lint

The hook already ran the lint after each edit. Run it once yourself to see the whole model at once:

```powershell
pwsh ./scripts/Invoke-Validation.ps1 -Only tmdl
```

**You should see:** `PASS  tmdl`. If there are errors, each line names the file, line number, and a rule code such as `TMDL003`. Paste the output into the chat and ask the improver to fix it.

<Checkpoint lab="07" step="5" />

### Step 6. Fix the report bindings

Report visuals refer to model objects by name. Renaming `dim_store` to `Store` in TMDL leaves every visual pointing at a table that no longer exists. The prompt asks the agent to rebind, but check it yourself:

```powershell
pwsh ./scripts/Test-ReportBindings.ps1
```

**You should see:** `PASS every report field exists in the model`.

If it fails instead, it lists each `visual.json` file and the missing field, for example `Entity 'fact_rx_fill' not found`. Ask the improver: "Fix the report bindings listed by Test-ReportBindings.ps1." It loads the `pbir-rebinding` skill, which explains the three parts of a field reference that must agree:

<RepoFile path=".github/skills/pbir-rebinding/SKILL.md" lines="17-40" />

<Checkpoint lab="07" step="6" />

### Step 7. Reopen the report in Desktop

<PlatformBadge kind="windows-only" />

1. Open `fabric\ContosoPharmacy.pbip` in Power BI Desktop.
2. Click **Refresh** on the **Home** ribbon.
3. Open the report page and check that every visual renders.
4. In the **Data** pane, hover over a column. The tooltip shows its new description.

**You should see:** tables named Date, Store, Medication, and Prescription Fill, and no visual with a red "Something's wrong with one or more fields" message.

## Troubleshooting

<details>
<summary>My edits disappeared, or the files changed back</summary>

Power BI Desktop had the project open while the agent edited the files, and it wrote its in-memory copy back when you saved or closed it. Close Desktop, run `git restore fabric` to go back to your last commit, and run `/improve-names-and-descriptions` again with Desktop closed.

</details>

<details>
<summary>The agent renamed more than it should, or started adding measures</summary>

Reject the extra changes in the diff (right-click the file in Source Control, then **Discard Changes**), and remind it of the scope: "Only names, descriptions, hidden keys, and summarization. No measures." The prompt file lists the scope, but agents sometimes read the whole assessment and try to do everything.

</details>

<details>
<summary>Visuals are blank or show "Something's wrong with one or more fields"</summary>

A visual still refers to an old name. Run `pwsh ./scripts/Test-ReportBindings.ps1`, then ask the improver to fix the files it lists. Reopen the project in Desktop afterward. Desktop doesn't reload PBIR files while it's open.

</details>

<details>
<summary>The handoff button isn't there</summary>

It appears only under the latest answer from the model-assessor, and only in VS Code. Pick **model-improver** from the agent dropdown instead. The handoff only saves you from typing the prompt.

</details>

<details>
<summary>The lint reports TMDL001 or mixed indentation</summary>

TMDL uses tabs. If you edited a file by hand, VS Code may have inserted spaces. The repo's `.vscode/settings.json` sets tabs for `.tmdl` files. Open the command palette (**Ctrl+Shift+P**), run **Convert Indentation to Tabs**, and save.

</details>

## Recap and next

You used a handoff to move from a read-only assessment to an agent that edits, scoped the work with a prompt file, reviewed an agent's TMDL diff, and fixed the report bindings that every rename breaks. The model now has business names, descriptions, hidden keys, and correct summarization, but it still has a missing relationship and no measures.
