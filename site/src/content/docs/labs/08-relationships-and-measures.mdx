## Why this matters

Business names make a model readable. Relationships and measures make its answers correct. The baseline model repeats category totals because Medication does not filter Prescription Fill, and it leaves time comparisons up to whichever DAX the agent guesses. In this lab you add the semantic structure that business questions need: single-direction relationships, a marked Date table, decoded fill type, and twelve explicit measures.

## Concepts

- **Single-direction filter:** dimensions filter facts, but facts do not filter dimensions. This keeps totals predictable and avoids ambiguous paths.
- **Marked Date table:** a real Date table with a key date column. Time intelligence measures use it instead of hidden auto date/time tables.
- **Auto date/time off:** the model should not contain hidden local date tables. One shared Date table controls calendar logic.
- **Explicit measure:** a named DAX calculation with a description, format string, and display folder. AI tools should use measures instead of implicit sums.
- **Decoded column:** a readable calculated column, such as `Fill Type`, that turns raw codes like `N` and `R` into business words.

## Troubleshooting

<details>
<summary>The relationship check still says Medication is missing</summary>

Ask the improver to inspect `definition/relationships.tmdl` and add the relationship from `'Prescription Fill'[Medication Key]` to `'Medication'[Medication Key]`. Then rerun `pwsh ./scripts/Test-ModelConventions.ps1 -Rule C07,C08`.

</details>

<details>
<summary>Date measures return blank</summary>

Check that Date is marked as the date table and that the relationship uses Prescription Fill[Fill Date] to Date[Date]. Also confirm auto date/time is off. Time-intelligence measures should use the Date table, not hidden local date tables.

</details>

<details>
<summary>The measure check reports a name mismatch</summary>

Use the exact names from `/add-core-measures`. `MoM %` is not the same as `MoM Percent`, and `Prescriptions Filled PM` is not the same as `Previous Month Fills`. Rename the measure and rebind any visuals that used the wrong name.

</details>

<details>
<summary>Invoke-DaxQuestionTests.ps1 cannot find Desktop</summary>

Open `fabric\ContosoPharmacy.pbip`, refresh it, and wait until the model is loaded. The script finds the newest `msmdsrv.port.txt` under the Power BI Desktop Analysis Services workspace folders. If you have multiple Desktop windows open, close the extras or pass `-Port <desktop-port>`.

</details>

<details>
<summary>The ADOMD.NET download fails</summary>

The first run with `-AllowDownload` downloads from `nuget.org` into `.tools/adomd/` and checks a pinned SHA-512 hash. If your network blocks NuGet, skip the optional DAX test and rely on the TMDL, binding, and convention checks until you can run on a network that allows the package.

</details>
