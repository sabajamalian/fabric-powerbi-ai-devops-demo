## Why this matters

Before you build custom agents, you need to know what context Copilot already reads. Repository instructions set the rules for every chat. Path instructions add file-specific rules only when their `applyTo` pattern matches. `AGENTS.md` gives multi-agent tools a shared guide. This lab shows how to prove which files shaped an answer by checking References in VS Code.

## Concepts

- **Repository instructions:** `.github/copilot-instructions.md`, automatically applied to chat requests in the workspace.
- **Path instructions:** `.github/instructions/*.instructions.md`, applied when `applyTo` matches the files in context or the task.
- **AGENTS.md:** a root agent guide read by VS Code and other agent tools when enabled.
- **References:** the expandable list in a VS Code Chat response that shows instruction files, prompt files, and other context used.
- **Customization diagnostics:** a VS Code view that helps when instructions are not applied.

### Step 4. Create a path instructions file for rules

The lab check requires a new `.github/instructions/*.instructions.md` file whose `applyTo` pattern matches real repo files. Create `rules.instructions.md` for the YAML rules under `rules/`.

<Tabs syncKey="os">
<TabItem label="Windows">

```powershell
@'
---
applyTo: 'rules/**'
description: Rules for editing lab convention YAML files.
---
# Rule files

- Keep rule IDs stable because scripts, skills, and lab checks refer to them.
- Explain why a rule exists before changing thresholds or required objects.
- Run `pwsh ./scripts/Invoke-Validation.ps1 -Only customizations` after editing rules.
'@ | Set-Content -Path .github/instructions/rules.instructions.md -Encoding utf8
```

</TabItem>
<TabItem label="macOS">

```bash
cat > .github/instructions/rules.instructions.md <<'RULES'
---
applyTo: 'rules/**'
description: Rules for editing lab convention YAML files.
---
# Rule files

- Keep rule IDs stable because scripts, skills, and lab checks refer to them.
- Explain why a rule exists before changing thresholds or required objects.
- Run `pwsh ./scripts/Invoke-Validation.ps1 -Only customizations` after editing rules.
RULES
```

</TabItem>
</Tabs>

Open `rules/naming-conventions.yaml`, then ask Copilot: `What should I be careful about before changing a convention rule?`

**You should see:** the response uses your new guidance, and References includes `.github/instructions/rules.instructions.md`. The file has non-empty frontmatter with `applyTo: 'rules/**'`, and that pattern matches real files under `rules/`.

### Step 6. Check instruction diagnostics and settings

If a reference is missing, use VS Code's diagnostics before editing files blindly.

1. Open the Command Palette: **Ctrl+Shift+P** (macOS: **Cmd+Shift+P**), or **View > Command Palette**.
2. Run **Chat: Configure Instructions** to see available instruction files.
3. Run **Chat: Open Customizations** if your VS Code version has the Agent Customizations editor.
4. In the Chat view, open the **More Actions** menu, then look for **Diagnostics** when an instruction file is not applied.
5. Confirm these settings are enabled in `.vscode/settings.json`: `chat.includeApplyingInstructions`, `chat.includeReferencedInstructions`, and `chat.useAgentsMdFile`.

The VS Code docs say to use References when an `applyTo` pattern may not be matching, and to check those settings when instructions aren't applied.

**You should see:** your workspace instruction files listed, with source locations. No JSON or YAML parse errors should appear for `rules.instructions.md`.

## Troubleshooting

<details>
<summary>References don't show any instruction files</summary>

Check `.vscode/settings.json` for `chat.includeApplyingInstructions`, `chat.includeReferencedInstructions`, and `chat.useAgentsMdFile`. Then reload VS Code with **Developer: Reload Window** from the Command Palette.

</details>

<details>
<summary>Your new instructions file doesn't apply</summary>

Check the frontmatter exactly. The lab check expects a new `.github/instructions/*.instructions.md` file, an `applyTo` value, non-empty body text, and a glob that matches real repo files. `rules/**` matches the files in `rules/`.

</details>

<details>
<summary>Copilot answers with generic Power BI advice</summary>

Make sure the repo folder is the VS Code workspace root. If you opened only `fabric/`, VS Code won't find `.github/copilot-instructions.md` or `AGENTS.md` at the root.

</details>

<details>
<summary>The Command Palette labels differ from the lab</summary>

VS Code Copilot UI labels move. Use the closest command with **Instructions**, **Customizations**, or **Diagnostics** in the name, then confirm the file names in References.

</details>
