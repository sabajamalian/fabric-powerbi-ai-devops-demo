## Why this matters

You need your own repository, because later labs create branches, commits, pull requests, custom instructions, and local run files. The upstream repo is the template and checkpoint source. Your copy is the workspace where you can experiment safely. By the end of this lab, the local validation passes even though the semantic model is still intentionally weak.

## Concepts

- **Template copy:** a new GitHub repo created from the upstream lab repo. Lab checks fail if `origin` still points at the upstream repo.
- **Upstream remote:** a read-only remote named `upstream`, used by checkpoint restore. See [Scripts](/reference/scripts/).
- **Synthetic data:** deterministic CSV files committed to the repo. See [Synthetic data model](/reference/synthetic-data-model/).
- **Validation:** local checks for data, expected answers, TMDL, PBIR bindings, customizations, and hygiene.
- **Recommended extensions:** VS Code prompts you to install the repo's extensions from `.vscode/extensions.json`.

## Before you begin

- Finish [Lab 00](/labs/00-workstation-setup/) or have equivalent tools installed.
- Sign in to GitHub in your browser.
- Use a short local path on Windows, for example `C:\src\contoso-pharmacy-lab`. Spaces work, but short paths make tooling errors easier to read.

## Steps

### Step 1. Create your own repository from the template

1. Open the upstream repo in your browser: `https://github.com/sabajamalian/fabric-powerbi-ai-devops-demo`.
2. Select **Use this template > Create a new repository**.
3. Pick your GitHub user or organization as **Owner**.
4. Name it `contoso-pharmacy-lab` or another short name.
5. Choose public or private visibility.
6. Leave **Include all branches** off.
7. Select **Create repository**.

**You should see:** a new repo under your account. Its file list looks like the upstream repo, but the URL starts with `https://github.com/<your-github-user>/`.

<Checkpoint lab="01" step="1" />

## Troubleshooting

<details>
<summary>The template button is missing</summary>

Make sure you're on the upstream repo page, not a file view or a fork page. If GitHub changes the button label, use the green **Code** button menu and look for template creation from there.

</details>

<details>
<summary>The clone fails with a long path error on Windows</summary>

Run `git config --global core.longpaths true`, open a new PowerShell 7 terminal, and clone to a shorter folder such as `C:\src\contoso-pharmacy-lab`.

</details>

<details>
<summary>PowerShell blocks a script</summary>

Open PowerShell 7 and run `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`. If your device policy blocks that, run the script with `pwsh -ExecutionPolicy Bypass -File ./scripts/Initialize-DevEnvironment.ps1`.

</details>

<details>
<summary>Python packages fail behind a proxy</summary>

Use your company's approved proxy settings for pip. The script uses pinned hashes, so don't remove `--require-hashes` or install unpinned packages to work around the proxy.

</details>

<details>
<summary>Validation passes, but the model still looks bad</summary>

That's expected. Validation checks whether the repo is internally consistent. The baseline model is intentionally weak, and the later labs improve its AI readiness.

</details>
