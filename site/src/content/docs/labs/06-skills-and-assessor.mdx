## Why this matters

Instructions are always on. Skills are loaded only when their description matches the task. That keeps the normal chat context smaller, while still giving agents deep guidance when they assess or change the model. In this lab the assessor loads the repo conventions, writes a structured assessment, and offers a handoff without making the fixes itself.

## Concepts

- **Skill:** a folder with `SKILL.md` and optional references. Copilot reads the description first, then loads the body and references when needed. See [Skills](/reference/skills/#pharmacy-model-conventions).
- **APM:** Agent Package Manager. This repo uses it to install Microsoft's Skills for Fabric `semantic-model-authoring` skill into `.agents/skills/`.
- **Read-only by instruction:** the assessor has an `edit` tool so it can write `out/assessment.md`, but its agent instructions restrict edits to that file.
- **Deterministic convention check:** `scripts/Test-ModelConventions.ps1` reads `rules/*.yaml` and reports rule-coded findings. The agent explains and prioritizes those findings.
- **Handoff:** the assessor shows **Fix these findings**, but you do not click it until [Lab 07](/labs/07-handoffs-names-descriptions/).

### Step 5. Ask the assessor to fix one finding

In the same model-assessor chat, type:

```text
Fix the highest-severity finding now.
```

The correct behavior is refusal plus a handoff. The assessor has `edit`, but its instructions say the only file it creates or edits is `out/assessment.md`:

<RepoFile path=".github/agents/model-assessor.agent.md" lines="1-20" />

This is an instruction boundary, not a hard tool permission. Lab 11 adds hooks that make some rules deterministic by denying forbidden edits and logging post-edit lint.

**You should see:** the assessor explains that it cannot edit TMDL or PBIR, summarizes what should be fixed, and points you to **Fix these findings** instead of changing the model.

<Checkpoint lab="06" step="5" />

**You should see:** a completed model-assessor answer with the **Fix these findings** handoff button under it, plus `out/assessment.md` in the repo.

## Troubleshooting

<details>
<summary>apm is not recognized after pip install</summary>

`pip install --user` puts `apm` in your Python user Scripts folder, which often isn't on `PATH` (pip prints a warning naming the folder). Add it for this terminal session, then run `apm --version` again:

```powershell
$scripts = python -c "import sysconfig; print(sysconfig.get_path('scripts', sysconfig.get_preferred_scheme('user')))"
$env:PATH = $scripts + [IO.Path]::PathSeparator + $env:PATH
apm --version
```

To make it permanent on Windows, add that folder under **Settings > System > About > Advanced system settings > Environment Variables > Path** for your user, then open a new terminal.

</details>

<details>
<summary>The semantic-model-authoring skill check fails</summary>

This check is optional. If you want it to pass, rerun `apm install --only apm --target copilot` from the repo root and check for `.agents/skills/semantic-model-authoring/SKILL.md`. If APM installed globally, the check also looks under your home directory.

</details>

<details>
<summary>APM changed .vscode/mcp.json</summary>

You likely missed `--only apm`. Restore the workspace MCP config with `git restore .vscode/mcp.json`, then rerun `apm install --only apm --target copilot`. This repo manages MCP servers itself.

</details>

<details>
<summary>The assessor writes fewer than eight findings</summary>

Ask it to rerun `pwsh ./scripts/Test-ModelConventions.ps1 -Markdown` and rewrite `out/assessment.md` with one row per grouped finding. The check reads the table shape and count, not the chat answer.

</details>

<details>
<summary>The skill does not appear to load</summary>

Ask the agent, "Which skills did you use?" Then expand the chat references. If `pharmacy-model-conventions` is missing, restart the chat and ask specifically to assess names, descriptions, relationships, date table, and measures against the Contoso Pharmacy conventions.

</details>

<details>
<summary>The assessor starts editing TMDL</summary>

Reject the edit. Remind it: "You are model-assessor. Your only editable file is out/assessment.md." The restriction is in the agent instructions. Hook-enforced edit denials are covered in [Lab 11](/labs/11-copilot-cli-and-hooks/).

</details>
