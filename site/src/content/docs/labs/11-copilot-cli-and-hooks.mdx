## Why this matters

Instructions are guidance. Hooks are code. In this lab you run Copilot CLI from the repo, pick the same custom agents and skills, and watch a deterministic hook deny an unsafe edit before the agent can make it. Then you make a TMDL edit and see the post-tool hook run the local linter automatically.

## Concepts

- **Copilot CLI:** the terminal Copilot surface. GitHub docs say you install it with `npm install -g @github/copilot`, start it with `copilot`, trust the folder, and use slash commands such as `/agent` and `/skills`.
- **Repository hook:** a JSON file under `.github/hooks/*.json` that runs commands on lifecycle events. See [Hooks](/reference/hooks/).
- **preToolUse:** a hook event that can return `permissionDecision: "deny"` with a reason before a tool runs.
- **postToolUse:** a hook event that can add context after a successful tool call. This repo uses it to run the TMDL lint after `.tmdl` edits.
- **VS Code agent hooks:** VS Code documents agent hooks as preview. VS Code can load hooks from `.github/hooks`, but event names and OS-specific command fields can differ by version. Use Copilot CLI for this lab's hook checks.

## Before you begin

- You finished [Lab 10](/labs/10-question-tester-after/) or restored `lab09-complete`.
- You ran `pwsh ./scripts/Initialize-DevEnvironment.ps1` in Lab 01, so `.venv` exists. The hook wrappers do nothing if `.venv` is missing.

- Close Power BI Desktop if it is open. This lab may touch TMDL text and then restore the demo edit.

### Step 8. Compare hooks with instructions

Read the guardrail side by side with the evaluation instructions.

<RepoFile path=".github/instructions/evaluation.instructions.md" lines="7-13" />

The instruction says not to read or edit answers. The hook enforces the dangerous parts with code. That means a prompt injection can tell the agent to ignore instructions, but it still can't edit `data/generated/` or `evaluation/expected/` through a normal tool call when the hook runs.

<Aside type="note" title="VS Code preview status">
VS Code's agent hooks documentation says hooks are preview and can be disabled by organization policy. It also documents PascalCase event names such as `PreToolUse` and `PostToolUse`. This repo's lab check is based on the Copilot CLI log format from `tools/python/pharmacy_demo/hooks.py`, so use CLI for the required evidence.
</Aside>

**You should see:** the difference between advisory guidance and deterministic checks. The same policy appears in instructions for model behavior and hooks for enforcement.

## Troubleshooting

<details>
<summary>Copilot CLI isn't installed</summary>

Install it with the current GitHub Docs command: `npm install -g @github/copilot`. Node.js 22 or later is required for the npm install path. You can also use WinGet on Windows or Homebrew on macOS if those are allowed on your machine.

</details>

<details>
<summary>The hook says .venv is missing</summary>

Run `pwsh ./scripts/Initialize-DevEnvironment.ps1` from the repo root. The wrappers intentionally exit 0 when `.venv` is missing so a fresh clone still works, but the guardrails won't run until the Python tools are installed.

</details>

<details>
<summary>No denied event appears in session.log</summary>

Make sure you asked for an edit under `data/generated/`, `evaluation/expected/`, `.pbi/`, or `*.SemanticModel/Copilot/`. A read-only request doesn't trigger the deny. If the agent refused before using a tool, ask it to apply the edit so the hook can block the tool call.

</details>

<details>
<summary>No lint event appears after the TMDL step</summary>

The post-tool hook only logs lint when the tool input names a path ending in `.tmdl`. Ask for a direct edit to `fabric/ContosoPharmacy.SemanticModel/definition/tables/Date.tmdl`, not a general review or a command that doesn't pass the file path to the hook.

</details>

<details>
<summary>VS Code hooks behave differently</summary>

VS Code agent hooks are preview. Check **Developer: Show Agent Debug Logs** and your organization's policy settings. For this lab, use Copilot CLI because `Test-LabProgress.ps1 -Lab 11` reads `out/hooks/session.log` written by the repo's hook implementation.

</details>
